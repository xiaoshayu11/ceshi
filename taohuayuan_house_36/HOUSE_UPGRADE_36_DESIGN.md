## 1. 现有系统能力盘点（v1 已核，v2 增补 3 条）

v1 的盘点表（存档无 house 键、Inventory 可参数化复用、材料只能买、场景注册表缺 house、家具系统为零、Mesh 预算充足、NPC 菜单框架齐全）继续有效。第二轮新核实的三条：

1. **打工计时基准 = `now_unix`（游戏时钟）**。`PartTimeJob.remaining()` 用 `now_unix` 差值结算（PartTimeJob.gd:30-36），v1 声称"睡觉不影响打工"**技术上不成立**——睡觉一旦推进 `now_unix`，打工必然被跳过。要么接受，要么把打工改用真实墙钟（+0.5 工作单元）。
2. **钓鱼 = 主动小游戏**（FishingSpotInteractable → GameplayRoot.begin_fishing），无时间等待结算，睡觉不影响，也无刷点。
3. **挖掘冷却仅 8 秒**（AntiqueDig.gd `cooldown_sec=8`），睡觉窗口内最多多挖几十次，无经济意义；昆虫冷却按 `_cooldown -= delta` 实时走，不受时间跳影响。

这三条事实修正后，睡觉的真实风险面比 v1 估的更小、但也更清楚（见 §3.4 防刷量化）。

## 2. 数值锚定（v1 有效，v2 补净利口径）

实读 `data/prices.json` 与 `data/crops.json` 后的**净利**（v1 用毛收入，v2 修正）：

| 活动 | 计算 | 净利 |
|---|---|---|
| 白菜/块/600s | 种 5 → 收 2×12=24 | **19 铜** |
| 萝卜/块/480s | 种 4 → 收 2×10=20 | **16 铜** |
| 6 块田白菜并行 | 6×19 | ≈114 铜/10 分钟 |
| 打工（600s 档） | 200 铜/10 分钟 | 200 铜（与种田可并行） |
| 钓鱼 | 18~90/条，主动小游戏约 40~90 铜/分钟 | 高但占满注意力 |

**混合游玩口径：10 分钟 ≈ 300~400 净铜；1 小时 ≈ 1500~2000 净铜**（v1 的 1200~1800 偏保守，v2 上调后仍留摩擦余量）。
新手第 1 天实际模型：起始 200 铜，开 2 块荒地（60 铜+4 木≈100 铜）+ 种子 ≈40 铜，1.5~2 小时主动游玩 → **日末结余约 1800~2500 铜**。

## 3. 睡觉系统（v2 完整规范 · 延后到 3.6b 实施）

### 3.1 v1 冲突的根源

v1 同时写了"睡到次日 6:00"和"单次封顶 8 游戏小时"——18:00 上床时"睡到 6:00"=12 小时>8 小时，两条规则打架。

### 3.2 v2 统一规则（一条规则消灭冲突）

- **可入睡时段：游戏时间 22:00 ~ 次日 4:00**。此窗口内"睡到 6:00"的推进量天然 ∈ [2h, 8h]，**"固定 6:00"与"≤8 小时"合并为同一条约束，不再冲突**。
- 窗口外上床：提示「现在一点也不困」，不产生任何效果。
- 床升级差异废除：v1 的"瓦房床可睡自选时段"取消，瓦房床只是外观与氛围升级。

### 3.3 次数与各系统结算

| 项目 | v2 规则 | 依据 |
|---|---|---|
| 次数 | 每游戏日 1 次，`house.last_sleep_day`（elapsed_days）入存档 | 同日二睡提示"一点也不困" |
| 作物 | **跟随跳过**：生长按 `now_unix` 离线公式结算，睡醒即熟 | 现有机制零改动 |
| 打工 | **必须二选一**：a) 打工改真实墙钟计时（+0.5 工作单元，叙事="雇的人按现实时间干活"）；b) 接受打工被跳过（睡觉收益 +200/天，需重压平衡）。**推荐 a** | v2 新核实的硬事实 |
| 钓鱼 | 不受影响（主动小游戏，无等待结算） | 实读 FishingSpotInteractable |
| 挖掘 | 不受影响（冷却 8s，无刷点） | 实读 AntiqueDig.gd |
| 昆虫 | 不受影响（delta 实时冷却） | 实读 InsectSpotInteractable |

### 3.4 防刷量化（v2 用净利重算）

三闸（22:00~4:00 窗口 + 固定睡到 6:00 + 每日 1 次）封死后：
- 一晚最多把"一轮在长作物"提前催熟 → 每天白赚 ≤ 6 块白菜一轮净利 = **≤114 铜/天 ≈ 日收入的 6~8%**；
- 若打工按 v2 推荐 a 改墙钟，打工 200 铜/天不可刷；
- 挖掘/钓鱼/昆虫零刷点。
**结论：单日最大套利 ≈114 铜，属于"睡觉仪式感的合理奖励"量级，无滚雪球路径**（v1 的"无限跳→无限刷"漏洞在 v2 数学上不可能：每日 1 次 + 单次 ≤8h 封死了循环）。

### 3.5 不依赖睡觉的替代方案（第二轮审查后的定稿）

**定稿：什么都不做。** 白菜 600s / 萝卜 480s 均 <15 分钟，离线生长已覆盖，等待成本本身很低——**等待痛点被高估了**，睡觉的真实价值是仪式感与次日开端，不是省时间。

| 候选 | 内容 | 最终判定 |
|---|---|---|
| ~~催熟铃~~ | ~~花猫三娘/牛头大哥处花 50 铜让一块田立即成熟~~ | **已删除**（Gemini 第二轮判为冗余设计：等待 <15 分钟 + 3.6b 会实装睡觉，专门开发亏本道具无意义；50 铜 > 该块净利 19 铜，纯亏本救急，无人会用） |
| 什么都不做 | 维持现状（真实时间 + 离线生长） | ✅ **定稿采纳** |

### 3.6 延后评估（用户重点）

**结论：推荐延后。** 理由：
1. 睡觉要给 TimeSystem 加 offset（`now_unix = 真实时间 + offset` 入存档），是 3.6 唯一动核心时间语义的点，33 套件 983 断言的回归风险集中在这；
2. 3.6 去掉睡觉后，L1/L2 的"肉"重新分配为能进屋/储物/床存档/耳房/图鉴（见 §4），不依赖跳时间依然成立；
3. 睡觉规范（§3.2~3.4）本轮已定稿，3.6b 作为独立小阶段（估 **1.5~2 工作单元，含打工改墙钟**）随时可做，不返工；
4. 3.6b 唯一候选 = 睡觉（催熟铃已于第二轮审查后删除，见 §3.5）；

## 4. 家具系统衔接（v2）

### 4.1 赠送家具延后到 3.7

- v1"每级送 2 件家具"→ v2 改为**「落成礼」延后到 3.7 家具系统上线时一次性发放**（木屋落成礼 2 件 + 瓦房落成礼 2 件，按存档里的 `house.level` 最高达成记录补发），旧玩家不吃亏、3.6 期内没有"拿了不能用"的尴尬。
- 3.6 预留：存档 `house.furniture_slots`（int）与 `house.furniture`（数组，空），牛头大哥菜单显示「家具位：8（家具铺筹建中）」**诚实标注不可用**。

### 4.2 3.6 期内家具位的真实价值

诚实口径：3.6 的"家具位"是**存档承诺**而非可玩功能。3.6 期内体验得到的肉点改为下表打 ★ 的项：

| 档 | 当前版本可体验的功能（★=3.6 内真实可玩） |
|---|---|
| L1 木屋 | ★能进屋（全新室内场景）· ★30 格储物箱 · ★床=免费存档点（上床即存档，不跳时间）· 家具位 8（预留） |
| L2 瓦房 | ★耳房第二间（室内空间翻倍）· ★储物 90 格 · ★图鉴新增「家」页 · ★**耳房静态功能摆件 ×1（用途见下表，三选一待用户挑）** · 家具铺购买资格（3.7 生效）· 家具位 20（预留） |

**L2 静态功能摆件（不可移动、不占家具位、仅瓦房耳房内有）**——Gemini 第二轮提出的 L2 当期反馈补救，具体用途：

| 候选 | 交互用途 | 成本 | 可行性核实 |
|---|---|---|---|
| **荣誉账本（推荐）** | 交互打开账本，查看**累计赚取铜币 / 累计钓鱼条数 / 图鉴点亮数**等成长记录 | +0.25 工作单元（Wallet 需加 lifetime 计数器，当前无此字段，已实读确认） | ✅ 可行 |
| 全家福画框 | 交互弹家人台词 + 显示当前身家（读现有 `Wallet.coins`，零新数据） | ≈0 | ✅ 可行 |
| ~~留声机~~ | ~~交互播放 BGM~~ | — | ❌ **不可行**：全项目无 AudioStreamPlayer/BGM 通道（实读确认），需先建音频系统 |

### 4.3 「基础家具摆放提前纳入 3.6」评估

- 需要：家具定义（data/furnitures.json）+ 网格吸附 + 摆放/收回 UI 的最小子集，约 **+1~1.5 工作单元**，3.6 总量 6~7 → 8~8.5 工作单元；
- 且 3.7 仍要做完整版（旋转、吸附精修、更多家具），最小子集会有一次返工；
- **结论：不推荐提前**。违背"不要为加功能过度修改核心系统"的约束。若用户坚持，3.6 改为「3.6 + 家具最小集」两段验收。

## 5. 升级经济（v2 重核）

### 5.1 计算依据（全部来自实读数据）

- 新手第 1 天结余模型 ≈ 1800~2500 铜（§2）；
- 后续每天净盈余 ≈ 1500~2000（减去种子/开荒持续投入后取下限）；
- 竞争性支出：开满 12 块田共需 360 铜+24 木（≈600 铜），种钱循环每轮需垫种子 24~54 铜；
- 节奏目标：**第 1 天末买木屋（成就时刻），第 2~3 天攒瓦房（中期目标）**。

### 5.2 两个口径的裁定

| 口径 | 总价 | 玩家感受 | 裁定 |
|---|---|---|---|
| WorkBuddy 2250 | L1 450 / L2 1800 | 木屋第 1 天达成✓；瓦房第 2 天末~第 3 天达成✓ | **推荐**：与"两天努力"节奏吻合，且给开荒留了预算空间 |
| Gemini 3000+ | L1 600 / L2 2400+ | 木屋第 1~2 天；瓦房第 4~5 天 | 不推荐：房屋变成第二主线，挤压种田/钓鱼/开荒的预算感；且本作短会话试玩为主，4~5 天跨度试玩根本摸不到瓦房 |

**v2 定价区间：全档 2000~2600 铜，推荐点 2250。** 若实测第 2 天就能毕业，唯一调整旋钮是 L2 1800→2000（总 2450），不动结构。

### 5.3 v2 价格表（材料权重 ~30%，沿用"铜+木"语言 · **以下均为待用户批准的设计数值**）

| 档 | 材料 + 金币 | 合计 | 前置 |
|---|---|---|---|
| L1 木屋 | 木材×10 + 350 铜 | **≈450 铜** | 无 |

扣费一次性在牛头大哥菜单完成（材料+铜一次交齐，无"先买材料再交工费"两段式死锁）。

## 6. 建筑与室内（v2 补齐）

### 6.1 破屋落点与占地（待用户确认的默认值）

- **落点：农场原 HouseA 位置 x=-14, z=-8 附近**（第一版就建议此位，本轮细化）；
- **占地 footprint 6m×5m**，碰撞盒 6×3.2×5，门朝南（+Z，面向田区）；
- 约束：距最近田块边缘 ≥4m（不挡耕地路径与 45° 镜头视线）、不压主路、不入 WastelandField 的 12 块网格；
- Mesh 预算：三档合计约 40（农场现 160/400，余量充足）。

### 6.2 外观成长

| 档 | footprint | 外观要素 |
|---|---|---|
| L0 破屋 | 6×5 | 歪斜茅草顶、木板补丁墙、无烟囱、门口"危屋"木牌 |
| L1 木屋 | 7×6 | 原木墙、木瓦顶、门廊+石烟囱（冒烟粒子）、门前木灯 |

每档都是**整栋替换**（同一落点重建，非拼接），程序化构建器参考 CuteShop/GrayboxBuilding 模式；升级瞬间旧体块消失+新体块落成+一声音效，所见即所得。

### 6.3 独立室内场景 HouseInterior 结构

- 独立场景（SceneRouter 注册 `"house"`，**同步改 test_scene_router 负向用例**——换一个仍未注册的 id，不删断言）；
- 主屋单间 6×6 网格（1m 格），南墙门位 (3,0)；进门 spawn 在门内侧，出门回农场门口外 1m（沿用 `scene.from_town` 的返回坐标先例，存 `scene.from_house`）；
- L2 耳房：同场景东侧 4×4 区域，L2 后开放隔断门（L1 时该区域用隔断墙+锁闭判定，场景不重建）；
- 窗户透光、屋顶不可见（室内相机固定俯视 45°，与 farm/town 一致）。

### 6.4 家具摆放与室内扩建的兼容性

- 地面 6×6 网格即 3.7 摆放网格，家具位坐标由 3.7 的网格系统占用，3.6 只存数量；
- 房间区域用 `RoomRegion` 数组定义（main 6×6 / annex 4×4），3.7 加新房间（后院/阁楼）= 扩数组 + 开门判定，不动场景结构；
- 墙面预留挂点数据（3.7 挂画/灯笼用），本轮只定义不入存档。

## 7. 存档结构（v2 定稿）

```jsonc
"house": {                    // 可选字段，旧档缺省 → level=0，不 bump save_version（铁律 8）
  "level": 0,                 // 0 破屋 / 1 木屋 / 2 瓦房
  "storage": [],              // 储物箱 Inventory 序列化（L1 起可用）
  "furniture_slots": 0,       // 家具位数量（承诺值，3.7 生效）
  "furniture": [],            // 3.6 恒为空数组；3.7 落成礼/购买件入此
  "last_sleep_day": -1        // 3.6 恒为 -1；3.6b 睡觉用
}
```

旧档语义：旧档自动获得破屋（level=0）——**仍需用户最终确认**；若不想要，改为旧档 level=-1 无房。

# 《桃花源物语》3.6 房屋升级系统设计案

> 版本：v1.0（2026-11-21 23:30）· 状态：待用户拍板 A/B/C，未进入实施
> 主导：WorkBuddy 独立设计 · 交叉审查：Gemini（模式 B，见 `HOUSE_UPGRADE_36_GEMINI_REVIEW.md`）
> 结论速览见 `HOUSE_UPGRADE_36_RECOMMENDATION.md`

## 0. 设计目标

为玩家提供一套**每一级都有真实功能增量**的房屋升级系统，拒绝"换皮不换肉"。功能增量的锚点选五个玩家能直接摸到的机制：

1. **能进屋**（室内场景）
2. **储物容量**（解决 30 格背包的囤积痛点）
3. **家具摆放位**（3.7 家具系统的直接前置）
4. **睡觉跳时间**（把"等待作物成熟"变成主动决策）
5. **购买资格**（瓦房解锁家具铺，给 3.7 开门）

## 1. 现有系统能力盘点（兼容性核查，全部来自实读代码）

| 系统 | 现状 | 对 3.6 的影响 |
|---|---|---|
| 存档 `GameState.save_game()` | payload 键：save_version/timestamp/player/inventory/wallet/time/catalog/farm/npc/scene，**无 house 键** | 新增可选 `"house"` 字段，旧档缺省 level=0，**不 bump 版本**（铁律 8） |
| 背包 `Inventory.new(30)` | 容量 30 槽、堆叠 99，类已参数化可复用 | 储物箱可直接 `Inventory.new(容量)` 实例化，序列化进 house 字段 |
| 金钱 `Wallet` | 初始 200 铜；玩家实测档 250 铜 | 升级成本以铜计 |
| 材料来源 | 木材 buy 10/sell 8、石材 buy 15/sell 12，**只能向牛头大哥购买，无采集玩法** | 升级材料成本天然成为材料经济的主沉淀池 |
| 收入模型 | 打工：120s→30 / 300s→90 / 600s→200 铜；白菜 6 块田一轮(600s)≈144 铜；钓鱼 18~90/条；任务 tomb 奖 50 铜 | 数值锚定见 §5 |
| 荒地开垦 3.5 | 每块 30 铜+2 木，上限 12 块，`unlocked_plots` 已入存档 | 可作为 L2 的成长门槛条件 |
| 场景注册表 | `SceneRouter.REGISTRY` 仅 farm/town；测试已有 `"house"` 未注册负向用例 | A/B 方案需注册 `"house"`（HouseInterior），**并同步改该测试**（不能删） |
| 农场建筑 | 6 栋已被用户清空，农场 Mesh 160/400 | 破屋落点需用户拍板；三档外观 mesh 预算充足（约 15~40） |
| NPC | 牛头大哥在镇木匠铺 (4.8,0.1,6)，NpcInteractable+菜单框架齐全 | 升级入口=牛头大哥菜单加页签 |
| 家具系统 3.7 | **完全未开始**（PHASE3_PLAN：data/furnitures.json、网格吸附、Catalog 并类） | 本轮只预留"家具位"数值与存档结构，不实现摆放 |
| 时间系统 | `TimeSystem.now_unix()` 基于真实时钟推进，`set_now()` 可注入（测试用） | "睡觉跳时间"需给 TimeSystem 加 offset 支持，改动点集中但有设计风险（见 §6 风险） |
| 龙爷任务链 | QuestSystem 仅 tomb 一条，`unlocked_flags` 机制成熟 | C 方案的任务链要扩 QuestSystem 定义表 |
| 场景根 | GameplayRoot/TownRoot 继承体系成熟，可加 HouseRoot | 室内场景复用现有路由/存档/背包管线 |

**明确不存在的**（不要假设）：房屋数据结构、储物箱、室内场景、家具、睡觉、施工等待、采集木材玩法。

## 2. 数值锚定（三个方案共用的收入/成本基准）

- 10 分钟主动游玩 ≈ **200~350 铜**（长工 200 或 6 块田一轮 144+零散采集）
- 1 小时主动游玩 ≈ **1200~1800 铜**
- 木材 10 铜/根、石材 15 铜/块（牛头大哥买入价）
- 参照系：荒地开垦 30 铜+2 木/块（现有最贵的单项消费）

## 3. 方案 A「三档买断」：破屋 → 木屋 → 瓦房

**一句话**：经典经营三连跳，钱+材料换一整档功能，即时完工。

| # | 项目 | L0 破屋 | L1 木屋 | L2 瓦房 |
|---|---|---|---|---|
| 1 | 级数 | 3 级，L2 为本阶段终点 | | |
| 2 | 外观 | 歪斜茅草顶、木板补丁墙、无烟囱 | 原木墙+木瓦顶+门廊+石烟囱(冒烟)+木灯 | 白墙青瓦+飞檐+红灯笼×2+木质窗格+院门楼 |
| 3 | 室内 | 不可进入（提示"破得没法住人"） | 单间 6×6 网格（HouseInterior） | 主屋 6×6 + 耳房 4×4 两间 |
| 4 | 储物 | 0 | 30 格（1 木箱） | 90 格（木箱+大衣柜+耳房箱） |
| 5 | 家具位 | 0 | 8 位 | 20 位（主屋 12+耳房 8） |
| 6 | 材料+金币 | — | 木材×15 + 120 铜 ≈ **270 铜** | 木材×30 + 石材×15 + 350 铜 ≈ **875 铜** |
| 7 | 解锁 | 初始 | 牛头大哥处提交，即时完工 | 同左 + 前置「已开垦 ≥2 块荒地」 |
| 8 | 等待 | 无 | 无 | 无 |
| 9 | 防膨胀 | 成本 60% 押材料（木材/石材只能买→材料经济主沉淀）；铜成本 = 0.6 / 1.75 个"10 分钟劳动单位"；不返还材料；L2 即终点，后续膨胀走 3.7 家具消费 | | |

**每级功能增量（肉点）**：
- **L1**：能进屋 + 30 格储物 + 8 家具位 + **木床睡觉**（时间跳到次日 6:00，作物按离线生长正常结算）
- **L2**：储物 ×3 + 家具位 ×2.5 + **解锁家具铺购买资格**（花猫三娘上架家具页签）+ 床升级（睡到自选时段）

**优点**：结构最简单、与原 PHASE3_PLAN 的「破屋→木屋→瓦房」一致、验收点只有 2 个升级交互；三档成就感清晰。
**缺点**：成长是台阶式的，两跳之间没有中间目标；"肉"集中在两个节点。

## 4. 方案 B「模块化扩建」：哪里坏修哪里

**一句话**：没有固定等级，破屋底座 + 5 个独立功能模块，想先要什么买什么。

| 模块 | 内容（肉点） | 成本 | 前置 |
|---|---|---|---|
| M1 修屋顶 | 能进屋（室内 6×6）+ 8 家具位 | 木材×10 + 80 铜 ≈ 180 | 无 |
| M2 造木箱 | +30 格储物 | 木材×8 + 60 铜 ≈ 140 | M1 |
| M3 接耳房 | 室内扩为 8×8 + 家具位 +12（共 20） | 木材×20 + 石材×8 + 200 铜 ≈ 420 | M1 |
| M4 打大衣柜 | +60 格储物（共 90） | 木材×15 + 石材×5 + 180 铜 ≈ 345 | M1 |
| M5 瓦顶翻新 | 顶配外观 + **解锁家具铺** + 图鉴「家」页 | 石材×25 + 400 铜 ≈ 775 | M3 |

| # | 项目 | 内容 |
|---|---|---|
| 1 | 级数 | 无固定级；1 底座 + 5 模块，全买总价 ≈ 1860 铜 |
| 2 | 外观 | 每模块对应一处可见变化（补顶/屋内箱子/侧面耳房/大衣柜/换青瓦），所见即所得 |
| 3 | 室内 | M1 前 0 → M1 后 6×6 → M3 后 8×8 |
| 4 | 储物 | M2 +30 → M4 +60，可分开买 |
| 5 | 家具位 | M1 8 位 → M3 +12 |
| 6 | 成本 | 见上表，单价 ≤775 |
| 7 | 解锁 | 全部牛头大哥处购买，依赖关系如上 |
| 8 | 等待 | 无 |
| 9 | 防膨胀 | 单价小、按需买、每一笔立刻见效；总价 ≈ A 全档之和，不额外放水 |

**优点**：「肉感」最强——每笔钱都换到看得见摸得着的一件东西；玩家自主性强；天然兼容后续加新模块（院子/狗窝/晾衣架）。
**缺点**：建筑需组合拼接（同一栋屋 5 种状态组合，程序化可行但验收点从 2 个变 5 个）；UI 菜单更长；缺少"升级到瓦房"的整档成就感。

## 5. 方案 C「修葺任务链」：龙爷的托付

**一句话**：升级靠做任务解锁 + 施工等待一天，铜成本减半、时间成本加倍。

| # | 项目 | 内容 |
|---|---|---|
| 1 | 级数 | 3 级（外观同方案 A） |
| 2 | 外观 | 同 A 三档，另加施工期占位（脚手架+茅草堆） |
| 3 | 室内 | L0 不可进 → L1 6×6 → L2 6×6+耳房 |
| 4 | 储物 | L1 30 格（任务奖励「旧木箱」）；L2 90 格 |
| 5 | 家具位 | L1 8；L2 20；**任务链直接奖励 2~3 件家具**（3.7 首件家具来源） |
| 6 | 材料+金币 | L1 木材×10 + 50 铜；L2 木材×20 + 石材×10 + 150 铜（铜成本 ≈ A 的一半） |
| 7 | 解锁 | 龙爷接「老屋修葺·上」（收木材/替牛头大哥钓 3 条鱼）→ 牛头大哥施工；L2 前置 tomb 任务链完成（剧情挂钩） |
| 8 | 等待 | **有**：提交材料后施工 1 个游戏日，当日挂脚手架，次日完工 |
| 9 | 防膨胀 | 铜成本压半，成本转移到任务时间；数值零膨胀，但节奏被任务链锁死 |

**优点**：叙事感最强，把修屋变成剧情体验；数值最克制；任务奖励送家具，3.7 衔接最自然。
**缺点 / 致命风险**：「1 游戏日等待」撞上现有真实时间系统——游戏日=真实日，"次日完工"等于**真等一天**；必须配合"睡觉跳时间"才能玩，而睡觉本身要改 TimeSystem。对测试和短会话试玩极不友好；任务链把升级节奏锁死，自由经营的玩家会被卡。

## 6. 三案共用的技术风险与前置决策

1. **破屋落点**：农场 6 栋建筑已被用户清空，破屋放哪、占多大，**必须用户拍板**（建议原 HouseA 位置 x=-14,z=-8 附近）。
2. **室内形态**：HouseInterior 独立场景 vs 屋顶掀开俯视，PHASE3_PLAN 写明「3.6 定」——本设计默认独立场景（复用 SceneRouter/存档管线最省），需用户确认。
3. **睡觉跳时间**：需 TimeSystem 加 offset（`now_unix = 真实时间 + offset`，入存档）。会加速作物/挖掘冷却——这正是设计意图，但会改变"现实同步"的既有语义，需用户确认接受。
4. **存档兼容**：house 字段可选、旧档默认 level=0 破屋、不 bump 版本（铁律 8）；旧档玩家会"平白多出一栋破屋"——需用户确认这是期望行为（还是旧档不给房子）。
5. **test_scene_router**：注册 `"house"` 场景后，现有「未注册 id 拒绝」负向用例要换一个仍然未注册的 id（改测试，不删断言）。

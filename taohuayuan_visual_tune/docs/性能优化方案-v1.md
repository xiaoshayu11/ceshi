# 正式镇区 219 DrawCalls 来源分析与优化方案 v1

作者：技术架构师 柯桥良 ｜ 范围：程序化镇区渲染成本，不改玩法/不碰碰撞口径 ｜ 依据：`tests/probe_env2b_stats.gd` 实测（335 MeshInstance / 26 MultiMeshInstance / DrawCalls 219，桌面 headless 窗口渲染）+ 指定源码静态审阅。

> **结论先行（重要纠偏）**：任务背景里「同色材质重复 new 导致无法合批 → 这是 219 的最大头」这一因果链，在 Godot 4.7 的渲染机制下**不成立**。普通 `MeshInstance3D` 的每个可见 surface 固定产生 1 次 draw call，引擎不会按材质是否相同自动合并 draw call；材质重复 new 的代价是**资源实例数 / shader 变体 / 状态切换 / 内存**，不是 draw call 计数本身。真正决定 219 的是「当前视锥内可见的几何实例数」。同时，源码事实是：`CuteShop.gd:38-45` **已经**做了按颜色的实例内材质缓存（第 42 行 `new` 只在缓存 miss 时执行；55/70/91 等行是 `material_override` 赋值，不是逐个 new）。因此材质复用是「降低状态切换 + 为手工合批扫清前提」的配套动作，**不能单独拿来承诺 DrawCall 下降**；DrawCall 下降必须靠 MultiMesh / 手工合并网格 / 剔除。

## 一、来源分解表（219 DrawCalls）

### 1.1 分解口径

- `Performance.RENDER_TOTAL_DRAW_CALLS_IN_FRAME` 统计的是**本帧实际提交**的 draw call：≈ 视锥内可见的 `MeshInstance3D` surface 数 + `MultiMeshInstance3D` surface 数（每个 MultiMesh 批次 1 次）+ `Label3D` 文字/描边提交 + 半透明对象按排序结果提交。**不是**全场节点数。
- 全场静态节点为 335 MeshInstance + 26 MultiMeshInstance = 361 个几何实例，而 DrawCall 只有 219 → 约六成几何实例进入本帧；这符合固定俯视相机下的视锥剔除结果。GLB 的 3 个 Mesh 实际含 7 个材质 surface（7 次提交，而非 3 次），`Label3D` 按字/描边另计，二者把可见率拉回约 55%~60%。
- 下表为**源码静态估算的可见贡献区间**，不是逐帧实测拆分；实测拆分需要在探针里按节点分组统计（见文末待实测项）。

### 1.3 「同色重复 new」的真实分布（纠正背景描述）

| 位置 | 现状 | 是否重复 new | 对 DC 的影响 |
|---|---|---|---|
| `CuteShop.gd:38-45` | `_mats` 按 `Color` key 缓存，**实例内**已复用 | 缓存 miss 才 new；跨 4 栋各建一份（最多 4 倍，非逐 mesh） | 无直接影响 |
| `CuteDecor.gd:45-48` `_mat()` | 每次调用都 `new` | 是（草/蘑菇/水面/长椅/木箱均走此路径） | 无直接影响，但浪费资源 |
| `TownGraybox.gd:167,182,184,377,541,471,518` | 每处直接 `StandardMaterial3D.new()` | 是（喷泉、广场、渐变、路牌、两个 MultiMesh 批次） | 无直接影响 |
| `RoadBuilder.gd:39-49` | 每条路 new 4 个材质，路内各段共享 | 3 条路 ×4 = 12 个 | 无直接影响 |
| `EdgeScenery.gd:41-44`、`GroundTint.gd:70,169` | 每个 baked variant / 批次 new 1 个 | 每个变体 1 个，量小 | 无直接影响 |
| `HouseBuilder.gd:19-29` | `static _mats` 全局按 key 缓存，屋顶 `duplicate()`（L181） | 否，**已是正确范式** | 可照抄到镇区 |

**结论**：材质重复 new 是「资源浪费 + 状态切换」，不是 219 的成因；把它当主因去改，会得到一个「代码更干净但 DrawCall 几乎不变」的结果。

## 二、材质复用清单

### 2.1 可共享（改为场景/全局缓存，按「颜色 + 语义 key」索引）

| 材质族 | 当前出处 | 建议 key | 备注 |
|---|---|---|---|
| 店铺墙/腰线/门窗/牌匾/窗玻璃 | `CuteShop.gd` `_mat(color)` | `shop:<color.to_html()>` | 把 `_mats` 从实例成员改 `static`，跨 4 栋共享；同色同参数才共享 |
| 住宅墙/装饰 | `GrayboxBuilding.gd` 逐栋 new | `farm:<color.to_html()>` | 3 栋 `wall_color/roof_color` 各异，单栋内部重复色共享 |
| 道路板/过渡缘 | `RoadBuilder.gd:39-49` | `road:<color.to_html()>` | 主街/两翼两色，各自路内已共享；跨路共享只影响资源数 |
| 草丛/蘑菇/长椅/木箱/水面 | `CuteDecor.gd:45-48` | `decor:<color.to_html()>:<alpha>` | **alpha 必须进 key**：水/波光是半透明，与不透明同色不能混用 |
| 广场/喷泉石件/渐变斑/路牌柱 | `TownGraybox.gd` 直 new | `town:<color.to_html()>` | 5 处石色可并作 1 个材质；喷泉 `water` 半透明独立 |
| 树带/草点/脚垫批次 | `EdgeScenery` / `GroundTint` / `TownGraybox._pad_batch` | `batch:vertex_color` | 全部 `vertex_color_use_as_albedo`，可全局共用 1 个 |

### 2.2 必须独立（严禁误伤）

| 对象 | 规则 | 源码依据 |
|---|---|---|
| 参与 `OcclusionFader` 淡化的屋顶材质 | **必须在命中前 `duplicate()`**；共享源材质可供多 mesh 读取，但淡化只能改副本的 `albedo_color.a` | `OcclusionFader.gd:125-141`：`_ensure_state` 对 `material_override` 路径 `duplicate()` 后置回 mesh；对 GLB surface 路径逐 surface `set_surface_override_material(dup)`。**当前实现已正确**，不要「优化」掉 duplicate |
| 程序化店铺屋顶（`CuteShop` 各 style 的 `Roof*`） | 目前由 `_mat(roof_color)` 生成、未预设副本，靠 fader 命中时 duplicate → **可以共享源**，但不得在共享源上直接改 alpha；若改成预复制，须逐 mesh 一份 | `CuteShop.gd:320,382,418,449,480`；`OcclusionFader.gd:129` |
| GLB `Roof_All` 逐 surface 材质 | 7 材质中的屋顶 surface 保持逐 surface 独立；fader 已做 surface override duplicate。不得把 Wall/Decor surface 材质与 Roof 合并成同一实例后再直接改 alpha | `ShopUmbrella.gd:27-34`；`OcclusionFader.gd:133-138` |
| `HouseBuilder` 屋顶 | 已有 `mat.duplicate()` + `_Fade` 命名范式，照搬即可，勿回退 | `HouseBuilder.gd:180-183` |
| 灯笼发光材质 | `CuteShop.gd:282-285` 对 `_mat(Color(0.86,...))` **写 emission**；若改为全局共享，必须把 emission 纳入 key（建议语义 key `shop:lantern_bulb`），否则会把发光误加给同色普通材质 | `CuteShop.gd:282-285` |

### 2.3 落地改法（按风险从低到高）

1. **最小改动**：新增 `scripts/world/MaterialCache.gd`（`class_name`，`static var _mats: Dictionary`，`static func get(color: Color, tag: String = "") -> StandardMaterial3D`，key = `tag + ":" + color.to_html(true)`；`to_html(true)` 含 alpha）。把 `CuteDecor._mat`、`TownGraybox` 直 new、`RoadBuilder.build`、`EdgeScenery._mat`、`GroundTint` 批次材质改为走 cache。
2. `CuteShop._mats` 改 `static`，并把 `_build_lantern` 的 bulb 改用语义 tag（`tag="lantern_bulb"`），避免 emission 污染。
3. 屋顶材质**只共享源**；`OcclusionFader._ensure_state` 的 duplicate 路径保留并在注释里写死「禁止移除」。
4. 可选（资源预载路线）：把高频材质烘成 `.tres` 预载，省首次 shader 编译抖动；但会引入资源维护成本，一人团队**建议先只做字典缓存**。

**预期收益**：材质共享本身对 DrawCall 的下降 ≈ **0~5**（仅来自减少不必要半透明重复提交/状态回切）；真正收益是材质对象数从约 200+ 降到 40~60、shader 变体减少、以及为下一步合批提供同一材质前提。**不要把它当作 DC 优化的主手段汇报。**

## 三、合批可行与禁区

### 3.1 可合并（低风险，纯视觉、无独立碰撞、无遮挡注册）

| 目标 | 手段 | 预估 batch 数 / 省 DC | 前置条件 |
|---|---|---:|---|
| **道路段**（每路 1 路板 + 2 过渡缘） | `MultiMesh`（`use_colors=true`，板/缘同 BoxMesh 模板 + 尺寸烘进基）或按路合并成 1 张 ArrayMesh（顶点色） | 3 路 × 约 54 mesh → **3~6 批次，省可见 DC 约 20~30** | 无碰撞（`RoadBuilder.gd:8-12` 已明确），不动 y_offset / 段长 / 颜色 |
| 草丛 3×2 + 蘑菇 2×3 + 岩石 5×2 + 花 4×3 | 按 mesh 形状 + 颜色分桶 `MultiMesh`，参照 `TownGraybox._batch_box_decor` | 省可见 DC 约 **10~18** | 零碰撞；保节点名（测试清点）可留空 Node3D 壳 |
| 喷泉石件 5 个 + 广场路面片 | 同材质合并 ArrayMesh | 省 **3~5** | `water` 半透明层不参与 |
| 路灯 6×3 mesh | 按部件 MultiMesh（杆/灯罩/灯座各 1 批） | 省 **10~14** | 无碰撞；若灯有阴影需评估阴影 pass 变化 |
| 木桥 14 mesh 中的纯装饰件 | 合并/实例化 | 省 **3~6** | 桥面可走行部分保留原几何与碰撞口径 |
| 路牌柱 3 + 南口渐变斑 2 | MultiMesh | 省 **3~4** | Label3D 保持独立 |

### 3.2 禁区（绝对不能合并）

| 对象 | 原因 |
|---|---|
| `Wall_Body` / `Roof_Body`（`ShopUmbrella.gd:30-33`、`HouseBuilder.gd:67-75`） | layer1 行走碰撞 / layer4 遮挡射线 + `house_roof` 组，合并会同时破坏碰撞分层与 `OcclusionFader.register_roof` |
| `Door_Blocker`（`HouseBuilder.gd:76-82`，L1/L2）与店铺门洞墙段（`CuteShop.gd:126-145,182-199`） | 回归红线 D12「不按 F 也能进屋」；门洞必须真实留空或物理堵死，视觉合并不得吞掉门洞 |
| 可淡化屋顶的全部网格（`CuteShop.gd` 各 `Roof*`、`GrayboxBuilding._build_roof`、`house_l{0,1,2}.glb` 的 Roof surface） | fader 以 **mesh 为单位**建 `_states`（`OcclusionFader.gd:81,85`）；跨栋合并会导致「淡化一栋 = 淡化一片」，且 surface override 索引会错位 |
| `Decor_All` 与 Wall/Roof 之间 | 商业样板三层分工是资产契约（碰撞/遮挡/纯装饰），合并会污染 layer 与淡化 |
| `Label3D` 招牌、NPC 身体/头、交互入口 | 玩法可读性与交互实体，非纯静态装饰 |
| 26 个既有 MultiMesh 批次 | 已是最优形态；二次合并会丢失 `instance_positions` / `patch_origins` 等测试 meta |

### 3.3 分阶段建议

- **P0（低风险，先做）**：道路段 MultiMesh 化 → 草丛/蘑菇/岩石/花 MultiMesh 化 → 材质缓存统一。**不动任何建筑、屋顶、碰撞节点**。预期 DrawCall 219 → 约 **165~195**。
- **P1（中风险，P0 回归通过后再做）**：`CuteShop` / `GrayboxBuilding` **单栋内部**非屋顶同色零件合并（墙板、腰线、飞檐、门窗框、灯笼挂件）；保留原节点名空壳或 meta 供测试断言。预期再降 **20~40**。
- **P2（高风险，本轮不做）**：GLB surface 重导合并（需 Blender 侧改 7 材质 → ≤4）、跨建筑合并、屋顶批次化。触及资产管线与淡化正确性，收益不确定，**列为后续独立课题**。

### 4.2 风险与处置

| 风险 | 触发条件 | 处置（门禁） |
|---|---|---|
| 测试断言依赖节点名（`probe_env2b_stats.gd`、`test_map_graybox` 清点 Grocery/Bench/WoodBoxes 等） | 合批时删除源节点 | 保留空 Node3D 壳与原名，仅 `queue_free()` 内部 MeshInstance（沿用 `_batch_box_decor` 做法） |

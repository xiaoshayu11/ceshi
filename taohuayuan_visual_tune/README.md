| 规格项 | 调整前 | 微调后 | 幅度 |
|---|---|---|---|
| 色阶跨度 deep↔light | 0.38 | 0.285 | **-25%**（要求 20–30%） |
| 浅瓣半径 `lr` | r×0.48~0.78 | r×0.42~0.66 | 上限 -15.4%，浅斑面积约 -28% |

## 二、ENV-2② 伞盖屋顶微调

| 规格项 | 调整前 | 微调后 |
|---|---|---|
| 屋顶 rx / ry | 2.95 / 2.45 | **2.88 / 2.38** |
| 对墙外挑 | 0.49 m | **0.42 m**（要求 0.38–0.42） |
| 厚度 thick | 0.13 | 0.12 |
| 厚度递减 | ×(1−0.25t)，边缘 0.0975 | ×(1−0.38t)，边缘 **0.0744（-23.6%）** |
| 下表面收边 | 0.992 | 0.995（减厚唇） |
| 波纹幅度 | 0.025·cos(8θ)·t² | 0.023·cos(8θ)·t² |
| 面数 / Mesh / 材质 | 7724 / 3 / 7 | **不变**（只改顶点坐标非拓扑） |

**保留不动**：蓝灰材质色与 sRGB 线性反解口径、z_apex/z_drop（檐口高 3.43m）、segs/rings、10 根放射伞骨、4 檐柱、墙体/门窗/招牌/台阶、Wall(layer1)/Roof(layer4+淡化)/Decor(零碰撞) 三层分工。

**数值冲突裁决（请 GPT 留意）**：现状 rx=2.95 若再缩 8–10% → 外挑仅剩 0.20–0.29m，违反 0.38–0.42m 硬约束且屋顶压到檐柱。故按外挑优先取 rx=2.88/ry=2.38；"缩小 8–10%"以最初被否决的大檐口版 3.15/2.65 为基准累计达成（-8.6% / -10.2%），对当前版实缩 2.4% / 2.9%。这是两条要求数学上无法同时精确满足时的自洽解，若 GPT 希望以当前版为基准硬缩 8–10%，需放宽外挑要求，请明示。

## 三、219 DrawCalls 来源与方案（重要纠偏）

**纠偏**：Godot 4.7 普通 MeshInstance 不按材质自动合批（每 surface 固定 1 DC）；`CuteShop.gd` 已有实例内按色缓存 →「材质重复 new」不是 219 的主因，单独做材质复用仅省 ≈0–5 DC。真正大头是可见几何实例数。

| 来源 | 对 219 的可见贡献（静态估算） | 可优化性 |
|---|---:|---|
| 4 栋程序化店铺 | 55–75（最大头） | 部分 |
| 3 栋住宅 | 35–55 | 部分 |
| 道路段 | 25–35 | **最高性价比** |
| 散件（草/花/石/蘑菇）+ 路灯 + 喷泉 + 水体 + 桥 | 60–90 合计 | 多为纯视觉可合批 |
| GLB 样板（7 surface）+ Label3D（8–20）+ 26 既有 MultiMesh | 固定/不可动 | 保留 |

**P0 方案（未实施）**：道路段与地表散件 MultiMesh 化 → 预估 219→165~195；材质缓存同步做（收益≈0，但为合批扫清前提）。**P1**：单栋内部非屋顶同色零件合并，再降 20~40。**P2（不做）**：GLB surface 重导合并，触资产管线与淡化正确性。

**合批禁区**：屋顶淡化网格（fader 以 mesh 为单位建 state）、门洞与 blocker（回归红线 D12）、Wall/Roof/Decor 分工、26 个既有批次（带测试 meta）、Label3D/NPC。**本轮只出方案、未实施任何合批**，严守"不得为优化破坏碰撞与遮挡分工"。
